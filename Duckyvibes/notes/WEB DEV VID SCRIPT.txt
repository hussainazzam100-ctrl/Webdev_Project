Duckyvibes is a full-stack e-commerce website which focuses on gaming and technology products.

I am here to demonstrate and explain the main features of the website

Features: 

Duckyvibes Branding & Logo

The header contains a custom Duckyvibes logo image and the Duckyvibes brand name.

The logo also has a hover animation: it slightly enlarges and rotates when the user moves the mouse over it.

Feature: Interactive branding / hover animation.


MAIN FEATURES
Frontend
1. Product Catalogue
Products can be dynamically displayed and organized into categories through the category section allowing customers to view separate products groups which can be accessed through the list of categories given. This allows users to filter out products based on the type such as laptop, mouse or RAM.
 
Figure 4. Product catalogue view organized by category.

2. Search & Filtering
Users can search for products in real time and filter products by category.


3. Product Details
As mentioned above, each product has its own allocated product page which contains, Price, old price for marketing purposes, specifications and a short description of the product.
 

4. Shopping Cart
Users can add products, change quantities, remove products and view the total which has an inbuilt calculation mechanism where the amount varies based on original price of the product and quantities purchased by the user. The checkout button is only there for design which I was unable to enable to functionality due to time constraints.
 


5. Wishlist
This is a feature that is generic among similar websites as Duckyvibes. Users can save products and move them to the cart later.
 

6. User Authentication
Login information is sent to the Django backend for authentication and allowing the user to be labelled either as customer or admin. Customers can view the default website with products and Wishlist items. On the other hand, individuals with administrative access can use crud functions and view various orders which were not made available due to time constraints.
 

7. Admin Management
As mentioned above, admin management involves authorized users to view, add, delete and edit products. This feature was inspired by my time in a shop as a salesclerk where I had to use crud functions for retail items and only, I had access to username + password as roles were assigned to each of the staff.
 

8. Backend Integration & Fallback System
Currently, Products are loaded from Django and to load them the Django server must be online. So, I made a fallback dataset to counter a scenario where Django server fails to be online within a grace period of 3 seconds and to allow the developers to see whether the server is connected and online, I included a banner that mentions either live mode or demo mode.
 


9. Error Handling
The JavaScript includes error handling for backend operations. For instance, for example if Admin username and password is incorrect or role is not given then the frontend displays a message which allows the web page stay active rather than leaving the user with a broken interface.
 

10. Product Database
This is the foundation of the website which stores items in a SQLite Database which can be accessed through the JSON file. After that, when the frontend requests for the product Django retrieves them from the database. This feature created the boundary between a static website and a full-stack application.
